# Public release readiness

**Status (2026-10-09): hold the Community submission.** Version `0.7.11` is a desktop beta with automated regression coverage and limited macOS app checks. It is not a general PDF editor or a tested multi-writer document store. The repository remains private. [Historical app checks](TESTING.md) and the [fault-injection audit](PRODUCTION_AUDIT.md) describe the evidence and its limits.

## Release blockers and decisions

1. **Concurrent writers:** a vault sync engine or another app can change a PDF between the final stale read and `Vault.modifyBinary`. A controlled race reproduced an overwritten external update. The README states the single-writer rule; enforce it in testing and support until a storage design can close the race. A further read does not make the write atomic.
2. **Recovery through failures:** verified draft export exists and has simulated damaged-source coverage. Exercise actual app termination, partial/disk-failure recovery, and interrupted file/folder moves in a disposable vault. Rename/index operations do not form a crash transaction.
3. **Platform and resource claims:** run the final assets in clean desktop vaults on macOS, Windows, and Linux, including Obsidian `1.13.7` if that remains the declared minimum. Cover Reading view, Live Preview, PDF tabs, pop-outs, themes, PDF links, zoom/rotation, keyboard/IME, unsupported PDFs, and external changes. Measure memory and responsiveness with representative large PDFs; a 24 MiB synthetic Node workload peaked near 1.2 GiB RSS in the earlier test process, not in Obsidian. Physical Wacom and pressure have not been verified or implemented.
4. **Distribution choice:** decide whether to publish this source repository after a final history review, or keep it private and create a separate public repository for built release assets. The latter requires granting the Obsidian Community directory GitHub App read access to the private source for scan/build verification. Neither repository access nor App installation is part of this preparation.

Other supported-scope limits remain in the [README](../README.md#current-limits): no OCR or handwritten-text recognition, no pressure-sensitive strokes, no editing checkboxes/radio/dropdowns, and rejection of encrypted, signed, XFA, and malformed PDFs. Native PDF viewer features are not all reproduced.

## Repository and submission checklist

- Keep the root `README.md`, `LICENSE`, and `manifest.json`. The current MIT license and bundled-font/library notices are present; review them against the exact build. Source, pinned lockfile, tests, and build instructions permit a reproducible build. Generated `main.js` stays out of Git and belongs in release assets.
- Preserve the installed ID `pdf-form-studio`. Confirm its global Community directory availability and the display name's uniqueness. Check `manifest.json` against the final app build: `0.7.11` currently matches `package.json` and `versions.json`; `isDesktopOnly: true` is required by the Electron import. Reassess `minAppVersion` from real app tests before release.
- Build from a clean checkout with Node 24 using `npm ci`, `npm run check`, and `npm run test:stress`. Inspect the generated bundle and install exactly `main.js`, `manifest.json`, and `styles.css` in a clean vault. Recheck dependency advisories at release time.
- After the distribution decision and approval, commit the release manifest on the distribution repository's default branch, create a GitHub release with an exact `x.y.z` tag matching `manifest.version`, and attach `main.js`, `manifest.json`, and `styles.css`. The current workflow makes a **draft** release; publishing it requires a separate decision.
- Submit the initial version at [community.obsidian.md](https://community.obsidian.md/) with an Obsidian account linked to GitHub. The directory reads the default-branch manifest and matching GitHub release. Use its preview scan before submission and address automated or human feedback with a new version and release. The old `community-plugins.json` PR procedure is not the current initial-submission path.
